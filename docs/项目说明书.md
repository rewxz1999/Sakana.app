## 1. 项目概览

### 1.1 是什么

**Sakana（🐟）是一个 Windows 桌面端「番剧管理 + 播放」客户端**，基于 Electron 构建，把下面这条链路完整地放在一个应用里：

> 找番（番剧表 / 搜索 / 详情） → 收藏与订阅（蜜柑计划 RSS） → 下载（内置 aria2 / 外部 qBittorrent） → 本地播放（libmpv / libVLC 双内核）
> 以及另一条独立链路：**在线播放**（Kazumi 风格规则引擎 → 搜索 → 选集 → 播放页嗅探 → 交给播放内核）与 **galgame 启动器/截图助手**。

它不是在线视频站的客户端，而是"本地资源管理器 + 多内核播放器 + 规则化在线取流"的组合体：

- 番剧元数据来自 **bangumi 网页镜像（bangumi.pro，HTML 解析）+ api.bgm.tv（JSON，需代理）**。
- 资源（种子/磁力）来自 **蜜柑计划 RSS**。
- galgame 元数据来自 **VNDB（KUN-A API）与月幕 Galgame（ymgal.games open API）**。
- 在线播放靠**用户可编辑的规则**（XPath / JSONPath 两套栈），内置 4 条、支持从 KazumiRules 仓库导入。

### 1.2 面向什么用户

| 用户画像 | 用到的功能 |
|---|---|
| 追当季新番、自己下载收藏的人 | 番剧表（周历）、订阅（字幕组选择 + 新资源确认）、下载与重命名、本地播放（HEVC/10bit/杜比音轨/内封字幕直接用内核播） |
| 不想下载、只想"点开就看"的人 | 在线播放规则（搜索 → 选集 → 嗅探 → 直连/中转播放），全程不看网页 |
| 喜欢整理自己观看记录的人 | 收藏（年份分组、已看完判定）、仪表盘统计、内置统计工具（序号 / 个人评分 vs bangumi 评分偏差 / 剧照 / 评价 / 看完时间）+ 导出图片 |
| 用 Sakana 当 galgame 启动器的人 | galgame 页（封面/简介/角色/游玩时长）、截图助手（全局快捷键 + 悬浮拍摄按钮） |

### 1.3 核心功能清单（按功能模块）

#### A. 番剧表 / 数据源（Schedule）

- 周历视图（周一~周日，可左右切换周，`weekOffset` 限制在 -4 ~ +4）；数据源默认 `https://bangumi.pro`，镜像 `bangumi.lol`、`api.bgm.tv`。
- **镜像并行竞速**：所有镜像同时请求，第一个 200 生效；`api.` 开头或含 `api.bgm` 的镜像自动走 v0 JSON 通道，其余走 HTML 解析。
- **会话内只联网一次**：启动后首次加载联网更新，此后本会话直接用本地数据（除非用户手动刷新 `force=true`）。
- 磁盘缓存：日历 30 分钟 / 详情 7 天 / 搜索 30 分钟 / 评分 7 天；日历页不含评分，进入某天后按需从详情页补全（并发 4）。
- 全部镜像失败 → 返回 `SourceError{kind:'ALL_DOWN'}`，前端据此提示"开启 VPN / 配置代理"。
- 图片统一走 `sakana-img://` 协议（主进程带浏览器 UA + Referer + 磁盘缓存）。
- 数据源配置页可改主源与镜像列表，并可"测试镜像"连通性。

#### B. 仪表盘（Dashboard）

- 订阅数 / 收藏数 / 工具数统计、观看与订阅历史、下载任务列表、时间段分布、**收藏类型分布圆环**（排除地区/播放类型标签）、**年度统计横向柱状图**（看过 / 看完）、继续观看入口。

#### C. 订阅与下载（Subscriptions / Downloads）

- 蜜柑计划 RSS 搜索，按**字幕组 / 集数 / 大小 / 日期**挑选资源。
- 两个语义不同的按钮：**「下载」= 订阅 + 立即下载**（`dl:subscribe-and-download`）；**「订阅」= 仅追踪该字幕组**（`dl:subscribe-only`）。
- 启动后延迟 4 秒自动检测全部订阅更新（并发 2），**只提示不自动下载**，需用户确认；已有下载任务的资源不再重复提示；无新资源时 `waiting` 状态自动复位。
- 下载器：内置 **aria2（JSON-RPC）** 或外部 **qBittorrent（Web API）**，可开**双下载器**（`downloader.dual`，按进行中任务数均衡分配）。
- 种子先下载再交给下载器（状态 `torrent`，不计入正片进度）；完成后按 `番剧名 字幕组 第XX集.后缀` 重命名（仅 aria2 路径实现）。
- 并发数可配置；失败可重试；删除未完成任务会清空其下载目录（目录被其他任务共用时不清）。
- 播放：本地模式读取下载目录，递归扫描（深度 ≤ 5）视频并自动匹配同名字幕。

#### D. 收藏（Favorites）

- 按年份分组 + 垂直年份条拖动定位；全源搜索（回车或按钮触发）；重点关心列表。
- **「已看完」**：手动标记 `watchedAt`，或观看记录覆盖全部集数（`isCompleted`）自动判定。
- 收藏时后台补全放送年份 / 类型 / 评分 / 集数（并发 3），修复"当年番剧被判为未知年份"。

#### E. 工具（Tools）

- 导入 Python 脚本（读三引号 docstring 作描述、同目录同名图片作封面、注释里的 `version:` 作版本）；界面内运行；一键导出《工具开发要求文档》（MD/TXT）。
- 数据接口：`--sakana-data <json路径>` 参数 **与** `SAKANA_DATA` 环境变量；运行超时 10 分钟；stdout/stderr 各截断到 200000 字符。
- **内置统计工具 v0.1**（无需导入）：列表管理、条目序号（`年份+2位序号`，如 `202601`）、个人评分与 bangumi 评分偏差、剧照 1-3、初始/完结评价、看完时间（可手动改）、导出为 PNG 图片（offscreen 窗口 2 倍渲染截图）。

#### F. Galgame

- 选择游戏 `.exe` 导入 → 扫描同目录（深度 ≤ 2）的说明文件（`游戏名:` 行、readme、与文件夹同名的行）与其它 exe 名推断查询词 → VNDB KUN-A API + 月幕 API 拉取元数据 → 封面/背景图/角色立绘下载到本地。
- 启动/退出即计时（`playtimeSec`），进程存活用 `process.kill(pid,0)` 轮询兜底（3 秒一次）。
- **游戏信息检测**（`settings.galgameDetect`）：每 2 秒用 PowerShell 读进程 `MainWindowTitle` 写入 `lastRouteInfo`。
- **截图助手**：随游戏启动而激活，全局快捷键（默认 `CommandOrControl+Shift+G`）+ 可选 56×56 透明悬浮拍摄按钮；**只截当前游戏窗口**（按标题匹配），截图前隐藏悬浮窗；最近截图读取该目录最新 30 张。
- 自定义封面 / 背景图（复制进 `userData/galgame-covers`）。

#### G. 播放器（Player）

- **双内核同一套 UI**：libmpv（默认、推荐）与 libVLC（备选、自动回退）；本地 / 在线 / 规则三种模式共用一个 `PlayerPage`。
- **画面比例**三态：`fit`（保持比例、可留黑边，默认）/ `cover`（裁剪铺满）/ `stretch`（拉伸铺满），两个内核各自实现（见 5.7）。
- **全屏控制栏悬浮窗**：因为原生视频画面永远盖在网页内容之上，全屏时另开一个透明置顶、默认点击穿透的窗口承载控制栏（见 5.8）。
- 控制栏 5 秒自动隐藏（`HIDE_DELAY = 5000`）；支持音轨/字幕切换、进度、倍速、选集抽屉、详情抽屉、截图、全屏；快捷键可自定义（14 个动作）。
- 内核不可用或编码不被 Chromium 支持时，回退 **FFmpeg 转码管线 → HTML5 `<video>`**。

#### H. 系统托盘

- 关闭主窗口弹三选一：「最小化到托盘 / 直接退出 / 取消」。
- 托盘**悬浮显示 198×282 小窗**（下载任务可暂停/继续 + 统计 + 观看历史）；双击回主界面；右键菜单「打开 Sakana / 退出」。

#### I. 在线播放规则（Rules）

- 独立规则管理页：规则增删改、启用开关、从 KazumiRules 仓库导入（gitcode 镜像优先、GitHub 兜底）。
- 内置 4 条规则：AGE、aafun（moonci.com）、TvTFun（API 型）、7sefun。
- 完整流程：规则搜索 → 选集（线路 + 剧集）→ 播放页（隐藏窗口 / 可见网页视图）→ 嗅探捕获视频流 → 交给当前内核；失败回退 FFmpeg 中转。详见第 6 节。

#### J. 设置（Settings）

- 5 套主题（sakura / matcha / midnight / obsidian / sunset），默认 `midnight`（白蓝）。
- 4 个独立小窗口：数据源配置、下载器配置、播放器设置、缓存设置；另有文件保存配置、导航栏背景、规则管理、Galgame 工具、错误日志、关于。
- 代理（HTTP / SOCKS5）同时作用于 axios 请求与 Electron session（网页视图 / 嗅探窗口 / 图片协议）。
- 错误日志查看页（内存 1000 条 + `log:read` 取最近 500 行文本，可复制）。

## 3. 目录结构（逐文件夹）

### 3.1 顶层

```

**`channels.ts` 与 `api.ts` 的关系（重要约定）**

- `channels.ts` 是**字符串常量的唯一来源**，主进程 `ipcMain.handle(CH.x)` 与 preload `ipcRenderer.invoke(CH.x)` 共用，避免字符串漂移。
- `api.ts` 是**面向渲染层的稳定契约**：一个方法可能对应一个通道，也可能在 preload 里对通道做包装（例：`ruleProbe.onFound`/`onDone` 都订阅同一个 `ev:rule-probe`，按 `payload.type` 分流；`downloads.onChanged` 对应 `ev:downloads`）。
- 因此**新增功能的正确顺序**是：`types.ts`（若有新数据结构）→ `channels.ts`（加通道）→ `ipc.ts`（实现 handler）→ `api.ts`（声明契约）→ `preload/index.ts`（接线）→ 渲染层调用。`preload/index.ts` 里的 `const api: SakanaApi = {...}` 会在漏接方法时直接编译报错。

### 3.7 `native/mpv/`

```
native/mpv/
├── binding.gyp             # node-gyp 配置：target sakana_mpv，源 src/addon.cc，
│                           #   NAPI_VERSION=8、UNICODE、user32.lib + gdi32.lib、/std:c++17 /utf-8
├── src/addon.cc            # 802 行纯 C++ N-API 插件（唯一源文件）
└── build/                  # 编译产物（gitignore）
    ├── binding.sln / *.vcxproj / config.gypi
    └── Release/sakana_mpv.node   # 实际加载的文件（打包时复制为 resources/native/sakana_mpv.node）
```

`addon.cc` 设计要点（源码注释已写明）：

1. **动态加载** `libmpv-2.dll`（`LoadLibrary` + `GetProcAddress`），编译期不依赖 mpv 库 —— 所以只需要 N-API 头文件（`node_api.h`）即可编译。
2. 在 Electron 主窗口内创建 **`WS_CHILD` 子窗口**作为视频输出表面，把该 HWND 通过 mpv 的 `wid` 选项交给 libmpv（与 `electron-vlc-player` 的嵌入方式同构，因此渲染层能用同一份布局）。
3. 只使用 **N-API**（ABI 稳定），故用本机 Node 头文件构建即可在 Electron 里加载。
4. 状态读取是**属性查询**（`time-pos` / `duration` / `pause` / `eof-reached`）由 JS 侧定时轮询，不做跨线程回调。
5. 给 mpv 设的默认选项：`vo=gpu`、`hwdec=auto-safe`、`keep-open=yes`、`idle=yes`、`force-window=no`、`input-default-bindings=no`、`osc=no`、`osd-level=1`、`ytdl=no`、`config=no`、`terminal=no`、`wid=<子窗口 HWND>`。
6. **z 序**：`RaiseChild()` = `SetWindowPos(HWND_TOP, SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE|SWP_SHOWWINDOW)` + `UpdateWindow` + `InvalidateRect`；`EnsureAttached()` 自愈（子窗口丢失则按当前宿主重建）。
7. 读取 `SAKANA_MPV_PARENT_WIDGET` 环境变量时改用"把视频窗口挂进 Chromium 渲染窗口内部"的备选方案（诊断用）。

导出的 16 个方法（`NAPI_MODULE` 注册，已核对）：`load` `create` `resize` `command` `setProperty` `getProperty` `state` `windows` `windowsOf` `raise` `ensureAttached` `hitTest` `reparentToRenderWidget` `setVisible` `destroy` `lastError`。
`src/main/services/mpv.ts` 里的 `MpvNative` 接口与其一一对应。

## 4. 进程与架构

### 4.1 三进程职责划分

| 进程 | 入口 | 权限 | 职责 |
|---|---|---|---|
| **主进程** `src/main/index.ts` → `out/main/index.js` | Electron `main` | 完整 Node + Electron 全部 API | 窗口/托盘/菜单、全部文件与网络 IO、下载器、播放内核、FFmpeg、协议注册、代理、持久化、日志 |
| **preload** `src/preload/index.ts` → `out/preload/index.js` | 每个窗口加载 | `contextIsolation: true` + `nodeIntegration: false` + `sandbox: false` | 只做一件事：把 `SakanaApi` 通过 `contextBridge` 暴露为 `window.sakana`，把 `invoke` 异常规范化为 `{ok:false,error}` |
| **渲染进程** `src/renderer/` | Vite 构建 | 纯浏览器环境（无 Node） | React 界面、状态管理、播放页布局与控件；所有系统能力都经 `window.sakana` |

**所有窗口的 `webPreferences` 一致**（`contextIsolation: true`、`nodeIntegration: false`、`sandbox: false`），差异只在窗口形态与启动参数：

- 主窗口：`frame: false`、980×640、最小 760×520。
- 副窗口（`openSmallWindow`）：`frame: false`、默认 760×560、最小 480×360、`additionalArguments: ['--sakana-small']`。
- 托盘面板：`frame: false`、198×282、不可缩放、跳过任务栏、`alwaysOnTop`。
- 嗅探窗口（ruleProbe / ruleSearchWebview）：`show: true` 但位于屏幕外 `x: -4000`、`skipTaskbar: true`、`focusable: false`、`backgroundThrottling: false`。
- 导出用离屏窗口（statExport）：`offscreen: true`。
- 截图助手悬浮窗（galgameTools）：56×56、`transparent: true`、`alwaysOnTop(true,'screen-saver')`，内容是内联 `data:text/html`。
- 全屏控制栏悬浮窗（playerOverlay）：`parent: owner`、与主窗口等宽高、`transparent: true` + `hasShadow: false`、`focusable: false`（**不抢主窗口焦点，否则播放快捷键失效**）、`skipTaskbar`、`alwaysOnTop(true,'screen-saver')`、默认 `setIgnoreMouseEvents(true, {forward:true})` 点击穿透（控制栏可见时才 `setInteractive(true)`）、`additionalArguments: ['--sakana-overlay']`、加载 `#/overlay`。

### 4.2 IPC 契约的组织方式

```

| **合计** | | **119** |

> **悬浮窗的消息路由模式（值得单独记住）**：`overlay:state` / `overlay:poke` / `overlay:action` 三个通道名在**两个方向上复用**——
> 播放页渲染层 `ipcRenderer.send(CH.overlayState, state)` → 主进程 `ipcMain.on` 收到后 `overlayWin.webContents.send(CH.overlayState, state)` → 悬浮窗渲染层 `onState` 收到；
> 动作方向相反：悬浮窗 `send(CH.overlayAction)` → 主进程转发给 `ownerWin` → 播放页 `onAction` 收到。
> 主进程在中间只做「状态下行、动作上行」的中转，**不留状态**，避免播放页与悬浮窗状态分叉。

## 5. 播放子系统

### 5.1 双内核：选择与回退

**选择逻辑（唯一入口）**：`src/main/services/playerEngine.ts → activeEngine()`

```ts
// 伪代码，与源码等价
if (process.env.SAKANA_FORCE_ENGINE === 'vlc') return 'vlc'          // 排障强制
if (process.env.SAKANA_FORCE_ENGINE === 'mpv') return mpvAvailable() ? 'mpv' : 'vlc'
if (settings.playerEngine === 'mpv' && mpvAvailable()) return 'mpv'  // 默认设置就是 'mpv'
return 'vlc'
```

`mpvAvailable()` = **原生插件存在**（`sakana_mpv.node`）**且** `libmpv-2.dll` 存在，两者缺一即不可用。

**回退链（三层）**

| 层 | 触发条件 | 行为 |
|---|---|---|
| ① 内核回退 | 设置要 mpv 但 `mpvAvailable()===false`，或 `mpvAttach()` 返回失败 | `engineAttach()` 记一条 `warn` 日志后直接 `attachVlc(win)` |
| ② 内核全部失败 | `attachVlc()` 也失败（找不到 libVLC / embed 抛错） | 渲染层 `vlcState` 从 `'trying'` 变 `'fallback'`，切换到 **HTML5 `<video>` + FFmpeg 转码管线** |
| ③ 取流回退（在线） | 内核拿到流地址 8 秒仍未开播（`playingRef` 仍为 false） | 调 `api.media.startLiveUrl()` 用 FFmpeg 带站点会话重新取流 remux，再喂给同一内核（`relayTriedRef` 只允许一次） |

**设置项**：`settings.playerEngine: 'vlc' | 'mpv'`，`DEFAULT_SETTINGS.playerEngine = 'mpv'`。播放器设置页只在 `player:assets` 返回 `mpv: true` 时允许选择 libmpv，否则按钮禁用并提示"缺少 libmpv 运行时"。

### 5.2 `playerEngine.ts` 调度

渲染层**只认一套 API**（`shared/api.ts` 的 `vlc.*`，历史命名），主进程按 `activeEngine()` 分发：

| 渲染层调用 | mpv 分支 | vlc 分支 |
|---|---|---|
| `vlc.attach(bounds)` | `mpvAttach(win, bounds)`（bounds 必填，默认 `{x:0,y:56,width:1280,height:640}`） | `attachVlc(win)`（忽略 bounds，用 `#vlc-host` 容器） |
| `vlc.play(path, referer, cookies)` | `mpvPlay` → `setProperty('http-header-fields', 'User-Agent…,Referer…,Cookie…')` + `loadfile replace` | `vlcPlay` → `setSource(path, {mediaOptions:[`:http-referrer=`,`:http-user-agent=`,`:http-cookie=`]})` |
| `vlc.setPlaylist(paths)` | 第一个 `replace`，其余 `append` | `player.setPlaylist(paths)` |
| `vlc.togglePause/seek/setVolume/setMute` | `pause` / `seek absolute` / `volume` / `mute` 属性 | 对应 VlcPlayer 方法 |
| `vlc.getState()` | `mpvGetState()` → 若 `!ready` 返回 `null`，否则映射 `{time,length,playing:!paused,volume,muted}` | `vlcGetState()` |
| `vlc.subtitleTracks/setSubtitle/addSubtitleFile` | 读 `track-list/*`（含 `external` 标记"（外挂）"）/ `sid` / `sub-add` | `getSubtitleTracks` / `setSubtitleTrack` / `addSubtitleFile` |
| `vlc.snapshot(path)` | `screenshot-to-file <path> video` | `takeSnapshot(path)` |
| `vlc.notifyLayout(bounds)` | `mpvSetBounds` + `mpvNotifyLayout()`（resize + 立即抢顶层） | `player.notifyLayoutChange()` |
| `vlc.detach()` | **两个后端都清理**（`mpvDestroy()` + `destroyVlc()`），避免切换内核后残留 | 同左 |
| `vlc.setAspect(mode, areaW, areaH)` | `mpvSetAspect(mode)`：`fit/cover/stretch` 分别设 `keepaspect` + `panscan`（`cover` 用 `panscan=1` 裁剪，`stretch` 用 `keepaspect=false` 拉伸） | `vlcSetAspect(mode, areaW, areaH)`：**绕过高层类**，`require('electron-vlc-player/dist/native').getBinding()` 直接调 `setAspectRatio` / `setCropGeometry`（传 `${w}:${h}` 或空串恢复自动），失败静默并记 warn |

**事件协议统一**：两个内核都通过 `CH.evVlc`（`ev:vlc`）向渲染层推同一套事件 —— `{type:'playing'|'paused'|'time'|'length'|'ended'|'error'|'cursor'|'playlistItem', ...}`。所以 `PlayerPage` 完全不需要判断当前是哪个内核。

两个内核各自的"补丁级"实现细节：

- **libVLC**：500ms 时间泵（暂停时不推，避免无意义 IPC）；200ms **系统光标轮询**（画面渲染在独立子窗口，渲染层收不到 `mousemove`，全屏时控制栏唤不出来）→ 光标一动就发 `{type:'cursor'}`；`controls: false` 关闭库自带的 overlay，控制条全部由渲染层自绘。
- **libmpv**：250ms 状态轮询；`playing` 判定为 `ready && !idle && !eof && !paused`（**必须按媒体状态而非 `paused` 边沿**，否则换集时 `paused` 不变就永远不再发 `playing`，渲染层会误判未开播并在 8 秒后错误切到 FFmpeg 中转）；`length` 变化 > 500ms 才发；`eof` 上升沿发 `ended`；同样有 200ms 光标轮询。

### 5.3 原生插件如何嵌入画面窗口（含 z 序的坑）

**这是本项目最容易踩的坑，`src/main/index.ts:36-51` 用一大段注释记录了完整结论，摘要如下：**

1. **视频窗口必须显式提升 z 序**（`SetWindowPos(HWND_TOP)`）。Chromium 的页面内容（`Chrome_RenderWidgetHostHWND` / DComp 合成层）会盖住普通原生子窗口 → 现象是**"有声音、一片黑屏"**。
   - 实测数据（源码注释）：不提升时屏幕抓取亮度 0.0，而 mpv 自身截图有正常画面 124.6；提升后同一位置亮度 109.3。
   - 与 `electron-vlc-player` 的 `RaiseAboveWebContent` 完全同理。
2. **不能依赖 `webContents` 的 `'paint'` 事件**：非离屏渲染下它不触发。所以采用"**首帧后立即提升 + 400ms 定时自愈**"。
3. 把视频窗口挂进页面渲染窗口（`Chrome_RenderWidgetHostHWND`）内部**也能显示**，但实测与"同级子窗口 + 提升"等价，故只作为诊断备选（`SAKANA_MPV_PARENT_WIDGET=1`）。
4. 无需关闭 Chromium 的 DirectComposition（实测保留该项同样正常）。

对应的实现位置：

| 机制 | 实现 |
|---|---|
| 创建子窗口 | `addon.cc → Create()`（`CreateChildWindow()`，默认选项里设 `wid`） |
| 提升 z 序 | `addon.cc → RaiseChild()`；JS 侧 `mpv.ts → raiseSurface()`（100ms 节流，`native.ensureAttached()`） |
| 定时自愈 | `mpv.ts → startRaiseWatch()`：`setInterval(raiseSurface, 400)` + 尝试监听 `paint`（离屏时才有机会触发） |
| 首帧后再挂一次 | `mpv.ts → startTimePump()` 内：`playing && pendingReparent` 时 `settle()` 立即 + 300ms + 1500ms 各执行一次 |
| 换媒体后必须重挂 | `mpvPlay()` 里 `pendingReparent = true`（新媒体的视频输出窗口会在首帧重建） |
| 隐藏/显示画面 | `mpvSetSurfaceVisible()` ↔ `addon.cc → SetVisible()`；探针网页视图要盖在同一区域时必须先隐藏视频窗 |
| 布局变化 | `mpvNotifyLayout()`：`resize` + 重置节流后立即 `raiseSurface()` |

**DPI / 物理像素**：`mpv.ts → toPhysical()` 用 `screen.getDisplayMatching(win.getBounds()).scaleFactor` 把渲染层上报的 CSS 像素坐标转成物理像素再传给原生窗口（`Math.round`，宽高最小 1）。

**渲染层如何上报视频区域**：`PlayerPage` 拿 `document.getElementById('vlc-host')` 的 `getBoundingClientRect()`，在 attach / 抽屉开合 / 全屏切换 / 控制栏显隐 / 窗口 resize 时调 `api.vlc.notifyLayout(bounds)`（libmpv 用它定位子窗口；libVLC 忽略 bounds 只用它触发内部布局通知）。

### 5.4 FFmpeg 中转（本机 HTTP 流）

**为什么必须是本机 HTTP 而不是自定义协议**（`transcode.ts` 顶部注释）：`sakana-live://` 只有 Electron/Chromium 认识，libVLC 与 libmpv 是独立媒体栈，拿到这个 URL 直接打不开（"此前中转回退因此在两个内核上都失效"）。改成 `http://127.0.0.1:<port>/live/<id>` 后，渲染层 `<video>`、libVLC、libmpv 三方都能播。

| 功能 | 函数 | 关键实现 |
|---|---|---|
| 启动中转 HTTP 服务 | `initLiveServer()` | `server.listen(0,'127.0.0.1')` 随机端口；`/live/<id>` 响应 `video/mp4`、无 `Content-Length`（Node 用 chunked，边转边播）、`Accept-Ranges: none`（不可 seek） |
| 本地转码流 | `startLive(path, {mode,startSec,height,videoCodec})` | `vcopy`：`-c:v copy`，**仅当源是 hevc/h265 时** 加 `-tag:v hvc1`（对 H.264 加该标签会让 FFmpeg 直接报 `Tag hvc1 incompatible with output codec id '27'` 退出）；`vtranscode`：`libx264 -preset veryfast -crf 22 -pix_fmt yuv420p`，源高 > 1080 时 `scale=-2:1080`；音频统一 `-c:a aac -b:a 192k -ac 2`；输出 `-movflags frag_keyframe+empty_moov -f mp4 pipe:1` |
| 在线流中转 | `startLiveUrl(url, {referer,cookies,userAgent})` | `-user_agent <浏览器 UA>` + `-headers "Referer: …\r\nCookie: …\r\n"`，`-reconnect 1 -reconnect_streamed 1 -reconnect_delay_max 5`，`-map 0:v:0? -map 0:a:0?`，视频 copy、音频转 AAC。**注释明确写了不能加 `-re`**：对 moov 在尾部的非 faststart MP4，`-re` 会把输入限速到实时，反而让首帧出不来（实测中转一直 0 字节） |
| 编码探测 | `inspectMedia(path)` | ffprobe `-print_format json -show_streams -show_format`；兼容集合 `COMPAT_VIDEO = {h264,av1,vp8,vp9,theora}`、`COMPAT_AUDIO = {aac,mp3,opus,vorbis,flac,pcm_s16le}`；无 FFmpeg 时按"兼容"处理 |
| 回放缓冲 | `pipeLiveOutput()` | `LIVE_BUFFER_LIMIT = 48MB`，超出从头丢；**FFmpeg 结束后不立即删会话**，留 `30s` `reapTimer`（0.2.0 起，原先 120s 白占最多 48MB 内存），否则短文件/重连会拿到 404 |
| 背压 | 同上 | `res.write()` 返回 false 只是内核缓冲满，**不能因此 destroy**（否则 libmpv/libcurl 报 `Transferred a partial file` 播不了）；只有积压 `> LIVE_CLIENT_LIMIT = 64MB` 才断开并记 warn |
| 全局唯一会话 | `startLive`/`startLiveUrl` 开头 | 先 `stopSession()` 掉所有旧会话（同时只保留一个转码会话） |

### 5.5 字幕

| 场景 | 机制 |
|---|---|
| **内封字幕**（MKV 等） | 交给内核。`vlcSubtitleTracks()` / `mpvSubtitleTracks()` 列表 → `setSubtitle(id)`；libmpv 侧读 `track-list/*` 并给外挂轨加"（外挂）"后缀（`external === true`） |
| **外挂字幕文件** | 本地模式自动匹配：`media.ts → listVideos()` 递归扫描（`MAX_SCAN_DEPTH = 5`，跳过 `.` 开头与 `__MACOSX`），视频扩展名 15 种、字幕扩展名 4 种（`.srt/.ass/.ssa/.vtt`）；匹配优先级：同目录**同名** → 同目录**前缀相同**（如 `xxx.chs.ass`）→ 同目录任意字幕；标签由文件名猜语言（简体/繁体/日文/字幕） |
| **手动选择字幕** | `dialog:pick-subtitle`（过滤 `srt/ass/ssa/vtt/sub`）→ `vlc.addSubtitleFile(path)`；**在线播放不支持**（界面直接提示"在线播放不支持选择字幕文件"，按钮禁用） |
| **HTML5 回退路径的字幕** | 走 `sakana-sub://local/<base64url>` 协议，主进程实时把 SRT/ASS/SSA 转 WebVTT：SRT 仅做 `,`→`.` 与块重排；ASS/SSA 只取 `Dialogue:` 行、剥 `{...}` 覆盖标签、`\N`→换行、厘秒×10 转毫秒；编码 UTF-8 优先，出现替换字符 `\uFFFD` 时用 `iconv-lite` 按 `gb18030` 解码，并去 BOM |
| **字幕轨刷新** | `refreshVlcSubs()`：为空时最多重试 5 次 × 700ms（libmpv 的 `track-list` 出来更晚），避免误报"未检测到字幕轨" |

### 5.7 画面比例

**已实现**（三态，`shared/types.ts` 的 `export type AspectMode = 'fit' | 'cover' | 'stretch'`，设置项 `settings.aspectMode` 默认 `'fit'`）：

| 模式 | 语义 | libmpv（`mpvSetAspect`） | libVLC（`vlcSetAspect`） |
|---|---|---|---|
| `fit`（默认） | 保持比例，必要时留黑边 | `keepaspect=true`、`panscan=0`、`video-aspect-override=-1` | `setAspectRatio('')` + `setCropGeometry('')`（恢复自动） |
| `cover` | 保持比例放大到填满，超出裁剪 | `keepaspect=true`、`panscan=1`、`video-aspect-override=-1` | `setAspectRatio('')` + `setCropGeometry('${w}:${h}')`（视频区像素比） |
| `stretch` | 不保持比例，直接拉伸铺满（会变形） | `keepaspect=false`、`panscan=0`、`video-aspect-override=-1` | `setCropGeometry('')` + `setAspectRatio('${w}:${h}')` |

调用链：渲染层 `api.vlc.setAspect(mode, areaW, areaH)` → `CH.vlcSetAspect`（`'vlc:set-aspect'`）→ `ipc.ts` → `playerEngine.engineSetAspect(mode, areaW, areaH)` → 按 `activeEngine()` 分发到 `mpvSetAspect` / `vlcSetAspect`。

> 实现细节：libVLC 侧 `electron-vlc-player` 的高层类没有暴露比例接口，`vlc.ts` 直接 `require('electron-vlc-player/dist/native').getBinding()` 拿底层 N-API 绑定调 `setAspectRatio`/`setCropGeometry`，取 `playerId` 失败或抛错时静默忽略并记一条 warn。切换模式时会写日志 `画面比例模式: <mode>`（mpv/vlc 各自 source）。
> 全屏控制栏悬浮窗里也能切比例：`OverlayAction` 含 `{type:'setAspect'; aspect: AspectMode}`（见 5.8）。

### 5.8 全屏控制栏悬浮窗（playerOverlay）

**要解决的问题**（`playerOverlay.ts` 顶部注释原话）：libmpv / libVLC 的画面是**原生子窗口**，永远绘制在网页内容之上，所以页面里的控制栏无法叠在画面上。全屏时若要让画面铺满整屏、控制栏又要浮在画面上，只能另开一个**透明、无边框、置顶**的窗口承载控制栏（`electron-vlc-player` 的 overlay 窗口也是同样思路）。

| 组成 | 位置 | 说明 |
|---|---|---|
| 窗口管理 + 消息中转 | `src/main/services/playerOverlay.ts` | `showOverlay(owner)` 建窗（覆盖主窗口 bounds）、`syncBounds()` 跟随位置、`setOverlayInteractive(bool)` 切点击穿透、`destroyOverlay()`、`pushOverlayState()` / `pokeOverlay()` / `sendOverlayAction()` |

## 6. 在线播放规则引擎

### 6.1 总体形状

技术栈刻意对齐 **Kazumi**（源码注释原话："播放规则引擎（Kazumi 同款技术栈）"）：

- **XPath 栈**：`xpath-html`（内部链路 parse5 → xmlserializer → xmldom → xpath）。
- **API 栈**：`axios` 取 JSON + `jsonpath-plus` 求值。
- 规则可**从 KazumiRules 仓库导入**（gitcode 镜像优先，GitHub 兜底），内置 4 条规则随应用更新。

### 6.2 规则数据结构（`shared/types.ts`）

```ts
interface PlayRule {
  id: string            // 'default-age' / 'repo-<name小写>' / 用户自建 uuid 风格
  name: string
  version: string
  baseUrl: string       // 用于相对链接解析 + Referer 兜底 + RULE_FIXES 匹配
  search: RuleSearchDef
  episodes: RuleEpisodesDef
  enabled: boolean
  createdAt: number
}
```

`RuleSearchDef`（**搜索**）：

| 字段 | 含义 |
|---|---|
| `type` | `'xpath'` 或 `'api'` |
| `method` | `'GET'` / `'POST'` |
| `url` | 含 `@keyword` 占位（`fillTemplate` 逐字段替换，query/headers 里的 `@keyword` 也会替换） |
| `headers` / `query` | **JSON 文本字符串**（不是对象），`parseJsonObject()` 兜底为空对象 |
| `bodyType` | `''` / `'form'` / `'json'`（仅 POST 有意义） |
| `listXPath` / `itemNameXPath` / `itemLinkXPath` | XPath 栈三件套 |
| `listJsonPath` / `itemNameJsonPath` / `itemSourceJsonPath` | API 栈三件套 |

`RuleEpisodesDef`（**选集 + 播放地址**）：

| 字段 | 含义 |
|---|---|
| `type` / `method` / `url` / `headers` / `query` / `bodyType` | 同上，但 `url` 里是 `@source` 占位 |
| `linesXPath` / `episodesXPath` | 线路列表 / 剧集列表（`linesXPath` 为空或 `//` 表示单线路） |
| `linesJsonPath` / `lineNameJsonPath` / `episodesJsonPath` / `episodeNameJsonPath` | API 栈对应字段 |
| `vars` | **响应变量**：变量名 → JSONPath，供 `playUrlTemplate` 用（内置 TvTFun 用 `{slug: '$.data.slug'}`） |
| `playUrlTemplate` | 播放页 URL 模板，可含 `@slug`、`@roadIndex`、`@episodeIndex` |
| `playQuery` | 追加查询参数，值里也可用上述占位符（值会被 `encodeURIComponent`） |

**占位符替换规则**：`fillTemplate(s, vars)` = `s.replace(/@(\w+)/g, (_, k) => vars[k] ?? '@'+k)` —— 未提供的占位符原样保留（便于排障时一眼看出漏传）。

**相对 XPath 处理**：`itemXPath(p)` 把以 `//` 开头的路径改成 `.//`（以条目节点为根的子树内查找）。

**命名空间处理（重要）**：`evalNodes()` 全文档查询时用 `doc.findElements()`（库内部已处理命名空间）；**相对条目查询**时用 `enhance()` 给每个标签名前缀 `x:`（跳过 `@` 属性与已带前缀的节点）再 hand 给 `doc.select()`。

### 6.3 两套栈的差异（写代码时最容易搞混的点）

| 维度 | XPath 栈 | API 栈 |
|---|---|---|
| 搜索条目 | `listXPath` + `itemNameXPath`（名称回退链：文本 → `title` → `alt` → 子 `img` 的 `alt` → 条目自身文本前 40 字）+ `itemLinkXPath`（取 `href`，若无则在直接子节点里找 `<a>`） | `listJsonPath` + `itemNameJsonPath`（回退 `item.name`）+ `itemSourceJsonPath`；**`link` 恒为空串，`source` 才是关键字段** |
| 选集页 URL | `new URL(entry.link || entry.source, rule.baseUrl)` | `fillTemplate(def.url, { source: entry.source || entry.link })` |
| 剧集项 | `{name: 节点文本, link: a 的 href}` | `{name: episodeNameJsonPath 或 e.name, link: ''}` |
| 播放地址（`rulePlay`） | **直接用剧集链接**：`resolveUrl(rule.baseUrl, episodeLink || entry.link || entry.source)` | `fillTemplate(playUrlTemplate, {...vars, roadIndex, episodeIndex})` + `playQuery` 拼参 |
| 内置示例 | AGE、aafun、7sefun | TvTFun |

> 因此：**API 型规则的最终播放地址是"模板拼出来的网页地址"，而 XPath 型规则是"选集页里那个 `<a href>`"**。XPath 型不产 `vars`（恒为 `{}`），API 型会产 `vars`（从选集接口响应里按 `vars` 的 JSONPath 提取）。

### 6.4 完整流程：搜索 → 选集 → 播放页 → 嗅探 → 交给内核

```
① 搜索    rules:search(ruleId, keyword)
          ├─ XPath：GET/POST 搜索页 → 解析条目（name/link/source）
          ├─ API：取 JSON → listJsonPath → 条目（name/link=''/source）
          └─ ★ 若 XPath 搜索拿到 0 条 → searchViaWebview() 回退：
               屏幕外真实浏览器窗口 loadURL(搜索页) → 等 3500ms（等 JS 渲染）
               → 在每个条目上下文里 document.evaluate（先相对 `//x` → 失败再全页）
               → 最多 30 条；20 秒空闲后自动关窗
② 选题    SharedView 里展示搜索结果；用户点一条 → rules:episodes(ruleId, entry)
          ├─ XPath：抓选集页 → linesXPath 分组（无则单线路）→ episodesXPath → {name, link}
          └─ API：抓选集接口 → vars（vars 的 JSONPath）+ linesJsonPath 分组 + episodesJsonPath
③ 播放页  rules:play(ruleId, entry, lineIndex, episodeIndex, episodeLink, vars)
          → 返回 {url}（XPath 型=剧集链接，API 型=模板拼接）
④ 嗅探（两条路径，优先 1）
   1) rule:webview-open（Kazumi 式可见 WebContentsView，贴在 #vlc-host 矩形上）
   2) 失败则回退 rule:probe-start（屏幕外隐藏窗口）
   两条路径内部都做 4 件事：
     a. webRequest.onBeforeRequest/onCompleted 捕获 resourceType='media' 或 media 扩展名
     b. CDP（Debugger Network 域，**先 Network.enable 再 loadURL**）读 XHR/Fetch 响应体，
        命中 '#EXTM3U' → m3u8、'<MPD' → dash；同时按 mime/URL 识别视频/音频响应
     c. 直接抓播放页 HTML 提直出地址（MacCMS `player_aaaa` → 百分号解码 → 常见字段
        `url`/`video`/`source`/`file`/`src`/`videoUrl` → HTML 里的裸直链），
        用 HEAD 校验（MIME 命中 video|audio|application/{octet-stream,vnd.apple.mpegurl,mp2t,x-mpegurl,dash+xml}），
        HEAD 不行再 Range GET(0-2047) 回退；通过则 encodeForVlc() 规范化 URL
     d. 逐子框架注入自动点击脚本（每个 frame 的 mainFrame + framesInSubtree），
        延迟多次执行（webview: 800/2200/4500/8000/12000ms；probe: 1200/3000/6000/10000ms）
     e. webview 额外做「嵌套播放器 iframe」二次解析（4s/9s/15s 各一次，最多 3 个 iframe）
   超时收尾：webview 30s / probe 20s 发 {type:'done', found, message, url}
⑤ 交给内核 PlayerPage 收到 {type:'found', url, kind, referer?, cookies?}
   → 命中即移除网页视图（用完即毁）+ 停止探针
   → refForPlay = (ev.referer !== undefined ? ev.referer || undefined : state.referer)
   → api.vlc.play(ev.url, refForPlay, ev.cookies)     ← 由 playerEngine 分发到 mpv/vlc
   → 8 秒内未开播（playingRef 仍 false）→ startFfmpegRelay(ev.url, refForPlay, ev.cookies)
   → 中转 12 秒仍未开播 → 报"该站点的视频流无法播放，请切换其它规则或退出"
```

**候选流优选顺序**（`pickBest()`）：`.m3u8` → 含 `master|index.m3u8|.mpd` → `.mp4/.flv` → 第一个捕获到的。

**命中判据**：`MEDIA_EXT_RE = /\.(m3u8|mp4|flv|mkv|webm|ts|m4s|mov)(\?|$)/i` 或 CDP 判定为播放列表/媒体响应。

### 6.5 Referer / Cookie 的三态语义（关键约定）

`referer` 字段在事件里**有三种状态**，代码注释明确写了：

| 值 | 含义 | 谁产生 |
|---|---|---|
| `undefined` | **未判定**：嗅探没有给出结论 → 播放时回退到规则站点 `state.referer`（`rule.baseUrl` 或规则的搜索页地址） | 从网络嗅探（webRequest/CDP）捕获到的流；`ruleProbe` 的 webRequest 分支 |
| `''`（空串） | **经校验确定不能带 Referer**：`resolvePlayable()` 用 HEAD/Range 试过，很多 CDN 带 Referer 直接返回 400 → 必须不带 | 直出地址路径（`extractStreamFromHtml` + `resolvePlayable`）与 webview 的 `reportFound(ok.url, 'direct', ok.referer ?? '')` |
| 非空字符串 | 校验通过且该 Referer 有效 → 播放时带上 | `resolvePlayable()` 返回值 |

渲染层的实现（`PlayerPage.tsx:292-294`）：

```ts
// referer 语义：undefined=未判定（回退规则站点）；''=经校验确定不带 Referer
const refForPlay = ev.referer !== undefined ? ev.referer || undefined : state.referer
```

**Cookie**：只有网页视图路径会采集 —— `collectCookies(url)` 用 `session.defaultSession.cookies.get({url})` 拼成 `name=value; …`，**异步补齐后才上报** `found` 事件（避免播放器取流时缺站点会话）。采集到的 Cookie 会同时传给：内核（libmpv 的 `Cookie:` 头 / libVLC 的 `:http-cookie=`）与 FFmpeg 中转（`-headers "Cookie: …"`）。

> 另外，`startRuleProbe`（隐藏窗口路径）使用 `session.defaultSession` 而非自定义分区 —— 注释说明自定义分区会导致页面加载 `ERR_FAILED`，改用默认会话 + `probeActive` 标志位忽略过期请求（因为 `webRequest` 监听无法注销）。

- 命名空间名会做安全化：`ns.replace(/[^a-zA-Z0-9_-]/g, '_')` → `<safe>.json`。

- 读：首次读盘，对象类型与 `fallback` **浅合并**（便于新增设置字段平滑升级）；数组类型只做类型校验。

- 退出时 `store.flushAll()`（`app.before-quit` 与 `ipc.ts` 的 `before-quit` 各调一次，幂等）。

| 源（仓库内） | 目标（包内） | 作用 |
|---|---|---|
| `resources/libvlc` | `libvlc` | libVLC 运行时（libvlc.dll + libvlccore.dll + plugins） |

| `native/mpv/build/Release/sakana_mpv.node` | `native/sakana_mpv.node` | **libmpv 的 N-API 原生插件**（注意路径被重命名，`mpv.ts → nativeModulePath()` 正是找 `process.resourcesPath/native/sakana_mpv.node`） |

`extraResources` 落在 `release/win-unpacked/resources/`（本机已构建产物目录结构已核对）：

```
release\win-unpacked\resources\
├── app.asar                    # 源码构建产物（out/）
├── app.asar.unpacked\node_modules\   # 需要落盘的原生依赖（如 electron-vlc-player 的 .node）
├── aria2\aria2c.exe
├── ffmpeg\{ffmpeg.exe,ffprobe.exe}
├── libmpv\{libmpv-2.dll,include\}
├── libvlc\{libvlc.dll,libvlccore.dll,plugins\}
├── native\sakana_mpv.node
├── icon.png
└── elevate.exe                 # electron-builder 自带资源（NSIS 安装阶段的提权辅助程序）
```

**原生插件与 `libmpv.dll` 如何随包分发（完整链路）**

1. `npm run mpv:build` 用 `binding.gyp` 编译 → `native/mpv/build/Release/sakana_mpv.node`。
2. `npm run libmpv:fetch` 把 `libmpv-2.dll` 放到 `resources/libmpv/`。
3. `electron-builder` 按 `extraResources` 把插件复制为 `resources/native/sakana_mpv.node`、把 DLL 复制到 `resources/libmpv/`。
4. 运行时 `mpv.ts → nativeModulePath()` / `dllPath()` **优先查 `process.resourcesPath`**（打包后），开发环境回退到 `appPath/native/mpv/build/Release/...` 与 `appPath/resources/libmpv/...`。
5. `loadNative()` 用**变量路径 `require(modPath)`** 加载插件（注释说明：交给运行时解析，打包后位于 `resources/native`），再 `mod.load(dllPath)` 动态绑定 DLL，并打印 `mpv-version`。
6. libVLC 同理：`electron-vlc-player` 的原生模块`vlc_binding.node` 在 `npm install` 时针对本机 Electron 版本编译，落在 `app.asar.unpacked/node_modules/`（`.node` 不能进 asar 执行）。

> **打包前检查清单**：`resources/{libvlc,libmpv,ffmpeg,aria2}` 四个目录必须都已 fetch，且 `native/mpv/build/Release/sakana_mpv.node` 存在 —— 否则 electron-builder 会因 `extraResources` 的 `from` 路径不存在而报错（或产出缺组件的包）。用 `SAKANA_ENV_TEST=1` 可以反向验证包内组件是否完整（见 9.2）。

### 9.2 常见问题排查步骤

> 通用前置：所有主进程日志都会同时写 `data/logs.json` 并打印到 stdout（`log.append`），设置里的「错误日志」页可看最近 500 行。**先看日志，再用下面的针对性开关。**

#### ① 黑屏 / 有声音没画面（最经典）

按顺序做：

1. **先分清是"没画出来"还是"被盖住"**：跑 `SAKANA_MPV_PIXEL_TEST=<视频文件>`。
   - 日志里 `mpv 自身截图 … 有画面（渲染管线正常）` + 区域亮度极低 → **解码正常但窗口被 Chromium 盖住**（z 序问题）。
   - `mpv 自身截图 … 接近纯色（渲染异常）` → vo 根本没出帧（往下查 2）。
2. 检查 z 序自愈是否在工作：`mpv.ts` 的 `startRaiseWatch()` 每 400ms 调 `ensureAttached()`；`addon.cc → RaiseChild()` 做 `SetWindowPos(HWND_TOP)`。若日志没有 `libmpv 已加载` / `libmpv 已嵌入`，说明插件或 DLL 没加载成功。
3. 试备选挂载方案：`SAKANA_MPV_PARENT_WIDGET=1`（把视频窗挂进 Chromium 渲染窗口内部），再跑一次像素自检看 `重挂后` 的亮度。
4. 试显隐自愈：`SAKANA_MPV_TOGGLE_VISIBLE=1`。
5. 看窗口树与遮挡关系：像素自检会打印 `自建子窗口下:` 与 `主窗口子窗口树:`；`SAKANA_PLAYERUI_TEST` 会打印 `命中(x,y): hitClass=… ourChild=…`（`mpvHitTest`）。若 `ourChild=false`，说明视频窗没在链上或被别的窗口压住。
6. 对照 libVLC：`SAKANA_FORCE_ENGINE=vlc`。若 libVLC 正常而 mpv 黑屏，基本可以判定是 z 序/子窗口问题而不是解码问题。
7. 远端/在线流黑屏：加 `SAKANA_MPV_VERBOSE=1` 看 mpv 自己的 HTTP 日志（UA/Referer/Cookie 是否如预期）。

#### ② 在线播放失败（搜不到 / 选不出集 / 播不了）

1. **规则层**：`SAKANA_RULE_TEST=<番剧名>` 看 4 条内置规则各自的搜索结果数与错误；若"0 条且无 error"，脚本会自动直接请求搜索 URL 并打印 HTTP 状态码 + 前 160 字 —— 这一步就能区分"站点挂了""被反爬""选择器失效"。
2. **站点改版**：如果 HTTP 200 但解析为空，用 `scripts/diag-xpath.js` / `diag-xpath2.js` 手工验证 XPath，然后把修正写进 `rules.ts → RULE_FIXES`。
3. **JS 渲染站点**（baimao / mgnacg / mutefun 等）：纯 HTTP 必然搜不到 → 确认 `searchViaWebview` 是否被触发（日志 `网页内搜索命中 N 条`）。
4. **嗅探层**：`SAKANA_PROBE_VERBOSE=1` 打开后能看到每一条 CDP `Network.responseReceived` 与每次 `emit`；判断是"没抓到候选"还是"抓到了但校验不过"。单独验证嗅探链路可跑 `SAKANA_PROBE_TEST=1`。
5. **直连失败但中转能播**（`SAKANA_ONLINE_TEST` 会同时验证这两条）：
   - 直连失败 → 观察是否自动中转（toast「直连未成功，正在通过内置 FFmpeg 中转该视频流…」）；强制只测中转用 `SAKANA_ONLINE_FORCE_RELAY=1`。
   - 中转也失败 → 检查 `ffmpegExe()` 是否为 `null`（未内置且没配路径）；`SAKANA_ENV_TEST=1` 可直接看到 `FFmpeg=未找到`。
6. **Referer/Cookie 三态**：日志里 `直连 Referer=… (不带)`、`libmpv 取流: UA=浏览器 Referer=… Cookie=… 字符`、`中转流启动` 就是判定依据；空串表示"经校验确定不能带 Referer"（见 6.5）。
7. **端口/代理**：嗅探窗口走 `session.defaultSession`（已 `applySessionProxy`）；若内网 HTTP 代理只放行一部分域名，表现为"HTTP 能取到、网页视图 `ERR_TIMED_OUT`"（`net.ts` 注释记录过这个坑）。
8. **本机中转端口**：`initLiveServer()` 用随机端口，日志 `中转流服务已启动: http://127.0.0.1:<port>/live/<id>`；若该行缺失说明服务没起来（端口/防火墙）。

#### ③ 副窗口空白

1. `SAKANA_SMALLWIN_TEST=1` 会逐个打开 13 个副窗口，并输出：`bodyLen`、`mainW/mainH`、`bodyBg/bodyColor`、`rootOpacity/rootDisplay`、`data-theme`、溢出量、以及**过滤后的 console error**（`did-fail-load` 也会被捕获）。
2. 加 `SAKANA_SMALLWIN_SHOT=1` 落 `.shots/*.png`，直接看渲染结果。
3. 若 `bodyLen` 正常但不可见 → 多为 CSS/主题变量问题（`data-theme` 是否正确、`main` 是否有高度）；若 `bodyLen=0` 且无 error → 检查该 hash 是否在 `App.tsx` 的路由表里、以及 `SMALL_WINDOW_TITLES` 是否有条目。
4. 页面抛错会由 `ErrorBoundary` 显示错误文本（不是白屏）；若连 ErrorBoundary 都没显示，考虑 preload 没注入（检查 `api.window.isSmallWindow` 是否按 `--sakana-small` 判对）。
5. 启动即错：`SAKANA_SMOKE=1` 看渲染层 console 与 `did-fail-load`。

#### ④ 内核回退/内核选不中

1. `SAKANA_ENV_TEST=1` 一次看全：`libVLC=<路径> ✓/✗`、`FFmpeg=…`、`aria2c=…`、`libmpv.dll=✓/✗ 插件=✓/✗`。
2. 界面侧：设置 → 播放器设置 →「重新检测」（`player:assets`）会返回 `{vlc, ffmpeg, aria2, mpv}` 四项状态；libmpv 缺失时按钮直接禁用并提示跑 `libmpv:fetch` + `mpv:build`。
3. 开发环境下 `activeEngine()` 的判定只看 `mpvAvailable()`（插件文件 + DLL 文件都在），**不看 DLL 能否真的加载**；真正加载失败会在 `loadNative()` 记 `error` 日志（`libmpv 加载失败: …` / `原生插件加载失败: …`），此时 `mpvAttach()` 返回 `{ok:false}` → `engineAttach()` 自动回退 libVLC 并记 warn。
4. 想强制复现回退：`SAKANA_FORCE_ENGINE=mpv`（当 mpv 不可用时返回 `'vlc'`）。
5. FFmpeg 路径：留空用内置；填了不存在时会**静默回落到内置**（`ffmpegExe()` 只校验 `existsSync`），排障时注意别被"填了没生效"迷惑。
6. 原生插件编译失败：确认 VS Build Tools（C++ 桌面开发）+ Python 3；若是 gyp 自身的 Python 兼容报错，跑 `python scripts/patch-gyp.py`。

#### ⑤ 打包后功能异常

1. `SAKANA_ENV_TEST=1` 在**打包版**里跑，重点看 `isPackaged=true`、`resourcesPath` 是否指向 `...\Sakana\resources`，以及四个组件是否都 ✓。
2. `npm run dist:dir` 出 `release/win-unpacked` 后直接对比目录结构（见 8.4），确认 `resources/native/sakana_mpv.node`、`resources/libmpv/libmpv-2.dll` 都在。
3. 中文路径 / 非 ASCII 路径下取流失败：优先怀疑 URL 转义（`encodeForVlc`）与 FFmpeg 参数拼接。
4. 下载器：内置 aria2c 打包后在 `resources/aria2/aria2c.exe`；若被安全软件拦截，日志会出现 `aria2c 退出 (code=…)` 或 `aria2 RPC 未就绪`。

#### ⑥ 播放器截图/媒体扫描异常

- 截图无文件：`vlc.snapshot` 依赖内核就绪（`need()` 会抛 `libVLC/libmpv 尚未就绪`）；HTML5 回退路径用 `player:screenshot`。日志有 `播放器截图已保存: <路径>` / `截图已保存: <路径>`。
- 本地视频列不出来：`SAKANA_MEDIA_TEST=<文件夹>` 会打印找到的视频数、每条的 `ep=` 与字幕标签，并逐个把字幕转 VTT 打印前 120 字；再验证协议层 `status/content-type/content-length/ACAO/Range`。
- 字幕乱码：`sakana-sub` 协议对 UTF-8 失败会回退 `gb18030`；若仍乱码可能既非 UTF-8 也非 GBK（待确认可扩展编码探测）。

### 10.3 能力边界（设计如此，但使用者容易误解）

| 限制 | 说明 |
|---|---|
| **平台** | 仅 Windows（盘符扫描、PowerShell 读窗口标题、NSIS、`.exe` 启动、`windowsHide`） |
| **中转流不可 seek** | `/live/<id>` 响应 `Accept-Ranges: none`、无 `Content-Length`（chunked 边转边播）；seek 靠重启 FFmpeg 加 `-ss` |
| **同时只允许一个转码会话** | `startLive`/`startLiveUrl` 会先停掉所有旧会话 |
| **中转回放缓冲 48MB** | 超出从头丢；FFmpeg 结束后会话保留 30 秒供晚到客户端重放（0.2.0 起） |
| **下载完成重命名只对 aria2 生效** | `renameDone()` 开头 `if (engineOf(task) !== 'aria2') return`；qBittorrent 路径不重命名 |
| **删除任务会删文件** | 未完成（非 `done`/`seeding`）任务被删除时 `rmSync(task.dir, {recursive:true})`；同目录被其他任务共用时跳过 |
| **订阅检测并发 2** | `checkAllSubscriptions()` 分批 2 个；启动时延迟 4 秒触发 |
| **日历会话内只联网一次** | 非 `force` 且本会话已成功更新 → 直接返回缓存；失败才回退"stale"缓存 |
| **评分补全依赖详情页** | 日历页不含评分 → 进入某天时按需抓详情（并发 4、7 天缓存）；无网时评分空缺 |
| **搜索缓存 30 分钟 / 详情 7 天** | 站点更新后短时间内看不到变化是预期行为 |
| **嗅探超时** | 网页视图 30 秒、隐藏窗口 20 秒；直连 8 秒未开播即转 FFmpeg；中转 12 秒仍未开播即判失败 |
| **在线播放不支持手动选字幕** | 界面明确提示"在线播放不支持选择字幕文件"，按钮禁用 |
| **galgame 截图只截当前游戏窗口** | 匹配不到窗口（最小化/无标题/未启动）时报错，**不会退化为整屏截图** |
| **游戏信息检测依赖窗口标题** | 每 2 秒一次 PowerShell（3 秒超时、强制 UTF-8）；标题变化才写入 `lastRouteInfo`；`galgameDetect` 默认关闭 |
| **galgame 游玩时长** | 以进程存活轮询（3 秒）+ `child.on('exit')` 结算，单次不足 1 秒不计 |
| **Python 工具** | 需系统 Python（`win32: python` / 其他 `python3`）；单次 10 分钟超时；stdout/stderr 各截断 200000 字符 |
| **缓存清理范围有限** | 只覆盖 `<缓存根>/img`、`<缓存根>/bangumi`、`userData/galgame-covers`，不清理 `tool-data`、`saves`、`galgame-covers` 之外的自定义目录 |
| **代理只作用于应用内请求** | axios（业务请求）与 `session.defaultSession`（网页视图/嗅探/图片协议）；已启动的外部下载器（qBittorrent）不受影响 |
| **无自动化测试 / 无 CI** | 验证依赖第 9 节的 `SAKANA_*` 自检与 `scripts/diag-*` 手工脚本 |
| **`bangumi.lol` 镜像不可用** | README 数据源表明确标注；仍在默认镜像列表里参与竞速（失败即被跳过，会拖慢首次请求到超时时间） |
| **打包需先准备运行时** | `resources/{libvlc,libmpv,ffmpeg,aria2}` 与 `native/mpv/build/Release/sakana_mpv.node` 必须齐全，否则 `extraResources` 缺项（见 8.4 检查清单） |

## 11. 术语表

| 术语 | 含义（结合本项目的具体用法） |
|---|---|
| **番剧** | 动画剧集（日本动画为主）；本项目里的核心管理对象，对应 bangumi 的 `subject`。 |
| **条目 / subject** | bangumi 的单个作品记录，有唯一数字 id（如 `subject/123456`）。`CalendarItem`、`FavoriteItem`、`Subscription` 都靠它关联。 |
| **番剧表 / 周历** | bangumi 的 `/calendar` 页面，按周一~周日列出当季在播番剧。本项目带 30 分钟缓存 + 会话内只联网一次。 |
| **数据源 / 镜像站** | 同一份数据的多个可用地址。本项目并行请求所有镜像，第一个返回 200 的生效；`api.` 开头走 JSON，其余走 HTML 解析。 |
| **字幕组** | 制作并发布带中文字幕视频的团队（如「[桜都字幕组]」）。在蜜柑 RSS 标题里通常是开头的 `[...]` / `【...】`，由 `parseGroup()` 解析，是订阅追踪的关键维度（"订阅 = 仅追踪该字幕组"）。 |
| **线路 / road** | 同一集在不同来源（或同一来源的不同备播源）下的多条播放路径。规则引擎用 `linesXPath` / `linesJsonPath` 分组，用 `roadIndex` 标识。 |
| **选集** | 从番剧的选集页解析出「线路 × 剧集」二维结构（`RuleEpisodeGroup[]`），用户点选后进入播放页。 |
| **嗅探** | 加载播放页并**抓取它实际请求到的媒体地址**（m3u8/mp4 等），再把这个地址交给本地播放内核。本项目有两条实现：隐藏窗口（`ruleProbe`）与可见网页视图（`ruleWebview`），并叠加 CDP 深度嗅探与 HTML 直出地址提取。 |
| **直出地址** | 播放页 HTML 里直接写着的真实流地址（MacCMS 的 `player_aaaa.url` 最常见，带一层百分号编码）。命中即用，省去等网页播放器跑起来。 |
| **中转 / FFmpeg relay** | 播放内核**直连取流失败**时，让 FFmpeg 带着同一套 UA/Referer/Cookie 去取流并 remux 成本机 HTTP 流，再喂给内核 —— 等于给播放器"换一套取流实现"。 |
| **内核 / 播放内核** | 真正负责解码与渲染画面的库。本项目有两个：libmpv（默认）与 libVLC（备选）。 |
| **内封字幕 / 外挂字幕** | 内封 = 封装在 MKV/MP4 里的字幕轨（由内核读取并切换）；外挂 = 独立的 `.srt/.ass/.ssa/.vtt` 文件（本地模式自动同名匹配，或手动选择）。 |
| **原生插件 / N-API** | 用 C/C++ 写的 `.node` 模块。本项目用 N-API（ABI 稳定）实现 `sakana_mpv.node`，动态加载 `libmpv-2.dll`，因此不必在编译期链接 mpv。 |
| **WS_CHILD / HWND** | Windows 窗口概念。libmpv 的画面输出是一个挂在主窗口下的子窗口（`WS_CHILD`），用 HWND 定位与提升 z 序。 |
| **z 序（z-order）** | 窗口的前后叠放顺序。Chromium 的页面内容会盖住普通原生子窗口，所以视频窗必须反复 `SetWindowPos(HWND_TOP)` —— 本项目"有声黑屏"的根因。 |
| **子窗口矩形上报** | 渲染层把 `#vlc-host` 的 `getBoundingClientRect()` 传给主进程，主进程按 DPI 换算成物理像素定位视频子窗口；这样两种内核能共用同一套 UI 布局。 |
| **分片 MP4 / frag_keyframe+empty_moov** | FFmpeg 输出可边生成边播的 MP4（moov 前置），配合 chunked 响应实现"边转边播"。 |
| **moov / faststart** | MP4 的元数据索引。moov 在文件尾部时，流式读取需先拿到整个文件；`transcode.ts` 注释记录了 `-re` 在这类文件上反而导致 0 字节的坑。 |
| **hvc1 标签** | MP4 里 HEVC 的 codec tag。视频复制（`-c:v copy`）输出 HEVC 时必须加 `-tag:v hvc1`；对 H.264 加则直接报错（本项目按实际编码判断）。 |
| **MPV/Dolby 音轨** | 杜比（AC-3 / E-AC-3 / DDP5.1、DTS）音轨；Chromium 不支持，两个内核支持，FFmpeg 回退路径会转 AAC 立体声。 |
| **Chromium 可直接播放** | 指 `COMPAT_VIDEO`/`COMPAT_AUDIO` 白名单内（h264/av1/vp8/vp9/theora + aac/mp3/opus/vorbis/flac/pcm_s16le）。不在白名单 → 需要走 FFmpeg 转码回退。 |
| **规则（PlayRule）** | 描述"某站点怎么搜索、怎么取选集、怎么拼播放页"的结构化配置，分 XPath 型与 API 型。内置 4 条，可从 KazumiRules 仓库导入。 |
| **XPath / JSONPath** | 前者在 HTML 文档里定位节点（本项目经 `xpath-html` 的 parse5→xmlserializer→xmldom→xpath 链路，注意 `x:` 命名空间前缀）；后者在 JSON 里定位值（`jsonpath-plus`，如 `$.data.videos[*]`）。 |
| **Kazumi / KazumiRules** | 一个开源番剧在线播放项目及其规则仓库。本项目规则引擎与规则格式刻意对齐它，并支持导入其仓库规则（gitcode 镜像优先、GitHub 兜底）。 |
| **站点改版修正（RULE_FIXES）** | 上游规则的 XPath 会因站点改版失效；本项目按 `baseUrl` 正则定点覆盖规则字段，比等上游更新更快，且每次启动写回存储。 |
| **Referer 三态** | `undefined` = 未判定（回退规则站点）／`''` = 经校验确定不带／非空 = 带这个值。CDN 对 Referer 的容忍度差异极大，见 6.5。 |
| **CDP（DevTools Protocol）** | 通过 `webContents.debugger` 使用，读 XHR/Fetch 响应体来识别 `#EXTM3U`(HLS) / `<MPD`(DASH) 播放列表；必须先 `Network.enable` 再加载页面，否则漏掉首批请求。 |
| **MacCMS / player_aaaa** | 一类常见影视 CMS 及其播放页里 `player_aaaa = {...}` 的变量，真实地址藏在 `url` 字段（一次百分号编码）。 |
| **蜜柑计划（Mikan）** | 番剧 BT 资源站，提供 RSS 搜索接口，本项目用它取种子/磁力与字幕组信息。 |
| **磁力 / 种子** | 磁力链接（magnet）与 `.torrent` 文件。本项目对种子是"先下载种子文件再交给下载器"（独立状态 `torrent`，不计入正片进度）。 |
| **做种（seeding）** | BT 下载完成后的上传状态。本项目把 `seeding` 视为"已完成"并触发重命名与订阅同步。 |
| **aria2 / qBittorrent** | 两个下载后端：aria2 内置（JSON-RPC，应用拉起进程、退出即停）；qBittorrent 是外部程序（Web API，应用不负责启停）。 |
| **双下载器** | `downloader.dual = true` 时同时启用两者，新任务按"当前进行中任务数较少者"分配，任务记录里以 `engine` 字段标记。 |
| **番剧表缓存 / 原子写入** | 本项目所有持久化都是"内存 + 250ms 防抖 + tmp 文件 rename 替换"，避免写一半崩溃导致 JSON 损坏。 |
| **副窗口 / 小窗口（openSmall）** | 按 hash 单例的独立 BrowserWindow（如播放器设置、规则管理、关于），渲染层通过 `isSmallWindow` 隐藏应用外壳并自绘标题栏。 |
| **托盘面板** | 悬停托盘图标弹出的 198×282 小窗（`#/tray`），可暂停/继续下载任务、看统计与观看历史。 |
| **截图助手** | galgame 的截图工具：全局快捷键 + 56×56 透明悬浮按钮，只截当前游戏窗口，随游戏启动激活、最后一个游戏退出时关闭。 |
| **galgame / 视觉小说** | 以剧情阅读为核心的日式游戏（含大量分支与汉化版本）。本项目提供启动器、游玩时长与截图管理。 |
| **月幕 Galgame / VNDB** | 两个 galgame 元数据源：月幕（`ymgal.games`，中文资料优先）与 VNDB（`api.vndb.org/kana`，原作名/评分/时长/标签/截图）。导入时两者都查，中文展示以月幕优先。 |
| **sakana-img / sakana-media / sakana-sub / sakana-live** | 本项目注册的 4 个自定义协议：远程图片代理（带 UA/Referer + 磁盘缓存）、本地视频（支持 Range）、本地字幕（实时转 WebVTT）、FFmpeg 转码流（已基本被本机 HTTP 取代，仅作服务未就绪时的兜底）。 |
| **悬浮窗 / overlay** | 一个独立于主窗口的透明置顶小窗口，用于把控制栏"叠"在原生视频画面之上（浏览器内容无法叠在原生子窗口之上）。本项目有两个 overlay：播放器全屏控制栏（`playerOverlay`，`#/overlay`）与 galgame 悬浮拍摄按钮。 |
| **画面比例（AspectMode）** | `fit`（保持比例、可留黑边）/ `cover`（保持比例放大到填满、裁掉超出部分）/ `stretch`（不保持比例、直接拉伸，会变形）三种模式，两个内核分别用各自的属性/几何接口实现。 |
| **离屏渲染（offscreen）** | 不显示窗口但可渲染，本项目用于统计列表导出图片（2 倍分辨率）。 |
