# 备用数据源调研（AniBase，v0.2.5 暂停中）

> 起因：`bangumi.pro` 被墙后曾考虑用 `https://anibase.net/zh-hans/` 兜底。
> 后来发现 **`https://bangumi.vip` 与 bangumi.pro 完全同款且可用**，于是优先接入 bangumi.vip，
> 本文档把 AniBase 的调研结论存档，需要时再继续。

## 一、AniBase 可用的公开接口

站点是 Vue 3 + axios 的服务端渲染页，前置 Cloudflare 校验（部分路径返回 403「Just a moment」）。

| 用途 | 地址 | 状态 |
| --- | --- | --- |
| 当日放送 | `https://anibase.net/zh-hans/api/air/animes` | ✅ 200，`{succeeded, weekday, air_animes:[{title, cover, url, format_label, genre_names, episodes}]}` |
| 首页榜单 | `/zh-hans/api/homepage/sections/{trending,top-rated,most-wanted,community-watchlist}` | ✅ 200，`{succeeded, data:[{id,title,cover,url}]}` |
| 条目详情 | `/zh-hans/anime/<id段>/<slug>` | ✅ 200 HTML（含 `og:title`、`og:image`、`meta description`、风格/季度、内嵌评分 JSON） |
| 搜索 | `/api/suggest?kw=<关键词>&type=all` | ❌ **401**「You do not have permission to access this」 |

**关键限制**：
1. **搜索接口对第三方封闭**：即使带站点自己的 `Accept-Id` 头、或在真实浏览器会话里（页面内 fetch）调用，
   依然返回 401 —— 说明它需要账号/授权，无法作为开放数据源。
2. 放送接口**只返回当前这一天**，不支持按星期查询（传 `weekday=` 等参数直接 401）。
3. 站点前有 Cloudflare 校验，主进程 axios 直连会间歇性拿到挑战页，
   必须走应用内的离屏真实浏览器（`src/main/services/offscreenFetch.ts`）。

## 二、若将来要恢复这项工作

- 离屏取数服务已经写好并验证可用（`offscreenFetch.ts`，导航式取数 + 自动等校验通过）。
- 需要补的是：条目 id 映射（AniBase 是 base62 短 id，如 `4xYD7`，与 bangumi 数字 id 不兼容，
  需要合成 id + 索引表）、详情页 HTML → `SubjectDetail` 的解析、以及「搜索退化为本地目录匹配」的取舍。
- 结论建议：**只在 bangumi 全部不可用、且 bangumi.vip 也挂掉时**才启用，作为最后的兜底。

## 三、bangumi.vip（当前采用）

- 与 `bangumi.pro` 同款：`/calendar`、`/subject/<id>`、`/subject_search/<kw>?cat=2` 结构完全一致，
  现有网页解析器（`bangumiHtml.ts`）可直接复用。
- 前置 Anubis（PoW 机器人校验）：直连只拿到 14KB 挑战页，**真实浏览器导航约 1~14 秒自动通过**。
- 图床是 `lain.bangumi.vip`，实测无 Referer 也放行。
